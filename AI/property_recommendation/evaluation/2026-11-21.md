8.21초가 걸려 콜드 스타트 개선이 필요하다.

## 검증 항목

반환된 25개 후보에서 다음 위반은 0건이었다.

- 보증금·월세 상한
- 주택·계약 유형
- 최소 면적·층
- 최대 건물 연식
- 중앙값 이하 조건
- 동일 건물·면적대 중복
- 점수 내림차순
- 점수 0~100 범위
- 전세 후보의 월세 포함
- 반환 개수 제한

같은 조건을 두 번 실행했을 때 후보 점수와 순서가 같아 계산 재현성도 확인했다.

## 판정

DB 가격·주거 조건만 보면 설명 가능한 MVP 추천 엔진으로 사용할 수 있다. 필수 조건을 먼저
거르고, 최신 실거래 가격·최근성·동일 건물 면적대의 표본 수로 순위를 계산하는 동작이
실데이터에서도 일관됐다.

다음 항목은 아직 추천 품질이 검증되지 않았다.

- 실제 교통 API를 사용한 통근시간·환승·배차 추천
- 사용자가 상위 후보를 실제로 선호하는지에 대한 정답 데이터
- 실거래 1건뿐인 후보의 신뢰도 표시
- 첫 요청의 콜드 스타트 성능

강서 전세 결과는 상위 5개 중 4개가 실거래 표본 1건이었다. 점수에는 낮은 근거량이
반영되지만, 화면에서도 `표본 부족`을 별도로 표시하는 것이 필요하다.

## 실행

DB 접속 환경변수를 설정한 뒤 실행한다.

```bash
python scripts/evaluate.py
```

평가 스크립트는 DB를 읽기만 하며 다음 조건을 자동 검사한다.

- 지역별 월세·전세 대표 조건
- 근사 예산 10% 허용
- 중앙값 이하 가격
- 결과 0건 경계값
- 필수 조건 위반과 중복
- 시나리오별 응답 시간
